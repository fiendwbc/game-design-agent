# **《基于 Gemini 多模态大模型的多智能体游戏分析与策划文档生成系统 —— 第一阶段技术方案》**

我们从最初的简单截图分析，演进到了一个支持**视频流理解**、**长按拖动操作**、**状态记忆**的完整 Agent 系统。

以下是该方案的核心要素摘要：

### 1. 核心目标
构建一个 AI 智能体，自动游玩 Windows 微信/抖音小游戏，通过视觉感知理解游戏机制，最终输出三份专业文档：**游戏策划案 (GDD)**、**数值反推表**、**美术风格分析报告**。

### 2. 技术栈架构

* **大脑 (Reasoning):** `Google Gemini 3 Pro`
    * 利用其 **2M+ Token 上下文** 处理长时间的游戏历史记忆。
    * 利用其 **原生视频理解能力** 分析动态特效、数值跳动和打击感。
* **中枢 (Orchestration):** `LangChain==1.2.1 && LangGraph`
    * 负责管理状态机（Thinking -> Acting -> Recording）。
    * 使用 **Pydantic** 强制约束 AI 输出标准的 JSON 格式指令。
* **眼睛 (Vision):** `mss` + `OpenCV`
    * `mss`: 毫秒级高速截屏。
    * `OpenCV`: 负责合成视频流，但不需做复杂的本地识别（全权交给 Gemini）。
* **手 (Action):** `pydirectinput`
    * 模拟 DirectX 底层硬件信号，确保鼠标点击和拖动能穿透游戏的反作弊或屏蔽机制。

### 3. 核心工作流循环 (The Agent Loop)

我们将流程标准化为 **“基于动作反馈的循环” (Action-Triggered Feedback Loop)**：

1.  **观察 (Observe):** 传入一段 2~5 秒的视频片段（包含上一轮操作后的界面反馈）。
2.  **思考 (Think):** Gemini 分析视频，决定下一步操作（点击/拖动/等待/结束），并输出 JSON。
3.  **行动 (Act):** Python 解析 JSON，执行鼠标动作（如 `MouseDown` -> `MoveTo` -> `MouseUp`）。
4.  **记录 (Record):** **关键点**——动作执行的同时，立即开启下一轮录制，捕捉动作产生的后果（如怪物掉血、弹窗打开）。
5.  **记忆 (Memory):** 将本轮的分析文本存入 `state['analysis_log']`，作为最终写文档的素材。

### 4. 关键技术难点解决方案

| 问题点 | 解决方案 | 优势 |
| :--- | :--- | :--- |
| **何时录像？** | **动作驱动录制** (Act -> Record Reaction) | 保证 AI 永远看到的是“因为我做了操作，所以游戏发生了变化”，符合因果逻辑。 |
| **坐标不准** | **归一化坐标系 (0-1000)** | 放弃像素坐标，让 AI 输出相对比例（如中心点 500,500），代码侧再映射回分辨率，大幅提升准确率。 |
| **长按/拖动** | **起点+终点逻辑** | 数据结构增加 `end_x`, `end_y` 和 `duration` 字段，支持点击、长按、滑动多种操作。 |
| **文档质量** | **LangGraph 状态累积** | 不依赖单次 API 调用，而是将几百步操作的“观察日志”全部喂给最后一步的 Prompt，生成内容极详尽。 |

### 5. 最终交付物生成逻辑

当 AI 判定游戏结束或达到指定步数时，触发 `Write_Doc_Node`：
* **输入：** `analysis_log` (可能包含 "第1步：点击开始，进入战斗" ... "第50步：Boss释放技能，特效为红色全屏AOE" 等详尽记录)。
* **处理：** 发送给 Gemini 3 Pro。
* **Prompt：** "作为资深策划，请根据这份详细的试玩日志，反推数值公式，绘制 UI 流程图，并总结美术风格。"

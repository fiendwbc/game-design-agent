# **《基于 Gemini 多模态大模型的多智能体游戏分析与策划文档生成系统 —— 第二阶段技术方案》**

> 本阶段在第一阶段“单智能体自动试玩 + 文档生成”的基础上，引入 **多智能体协作架构**，增强系统在机制理解、UI 流程抽象、数值反推与美术风格提取方面的专业度，使系统从「智能试玩机器人」升级为「自动化游戏策划工作室」。

---

# **1. 系统总目标（第二阶段升级版）**

构建一套 **多角色多智能体协同系统**，实现：

1. **自动试玩（探索/通关两种策略）**
2. **自动解析游戏机制 & 数值模型**
3. **自动构建 UI 交互流程图**
4. **自动分析美术风格与动效特征**
5. **自动生成三类专业文档**：

   * 游戏策划案 GDD
   * 数值反推表（CSV / JSON）
   * 美术风格分析报告
6. **自动自检（Consistency & Completeness QA）**

该系统可适用于：

* Windows 端微信小游戏 / 抖音小游戏
* 休闲类 / 动作类 / Roguelike / 消消乐 / 放置类等通用玩法
* 无需注入 DLL、不破坏反作弊
* 通用化的截图 + 操作 API

---

# **2. 第二阶段总体架构（Multi-Agent Orchestrated System）**

系统采用 **多智能体（Multi-Agent）+ LangGraph 状态机调度 + Gemini 大模型群** 架构。

核心由 **6 个智能角色**组成，每个角色专注于不同任务，通过 LangGraph 进行状态共享和协作。

## **2.1 多智能体角色划分**

### **① Player-Agent（即时操作智能体）——“执行者”**

负责基于视频反馈执行游戏操作。

* 输入：2~5 秒视频片段 + 局部状态（HP、金币、界面模式）
* 输出：标准化动作 JSON（click/drag/press/wait）
* 策略：探索优先 / 通关优先（可动态切换）

---

### **② Mechanics-Analyst Agent（机制与数值分析智能体）——“战斗与玩法解析者”**

从关键帧视频中抽取：

* 敌我血量变化 → **推断伤害模型**
* 掉落规律 → **推断经济系统**
* 技能行为 → **推断核心战斗循环**
* 关卡结构 → **推断玩法类型（Roguelike/塔防/跑酷/etc.）**

输出结构化 JSON，如：

```json
{
  "damage_event": {"skill": "bullet", "before": 120, "after": 98, " dmg": 22 },
  "core_loop": "战斗→拾取金币→结算→强化→下一关",
  "level_structure": "固定波数关卡"
}
```

---

### **③ UI/UX-Agent（界面流程分析智能体）——“界面架构师”**

自动识别 UI 屏幕的跳转关系，构建「可视化流程图」所需的节点/边集合。

输出例：

```json
{
  "nodes": ["主界面","关卡选择","战斗中","结算页"],
  "edges": [
    {"from":"主界面","to":"关卡选择","trigger":"点击开始"},
    {"from":"结算页","to":"主界面","trigger":"点击返回"}
  ]
}
```

---

### **④ Art-Style-Agent（美术风格智能体）——“视觉艺术评论员”**

从关键截图中总结：

* 主色调（色板）
* 立绘风格、UI 风格
* 镜头语言
* 动效风格（受击闪白、屏幕震动、特效遮罩等）

输出结构化描述。

---

### **⑤ Doc-Writer-Agent（文档生成智能体）——“策划文档作者”**

读取所有角色产生的结构化记忆，生成专业格式的：

* GDD
* 数值反推文档
* 美术风格报告

文档使用模块化 Schema，统一结构，支持机器解析和版本控制。

---

### **⑥ QA-Critic Agent（自检智能体）——“文档质量审查员”**

检查文档：

* 是否缺失模块？（如成长系统、经济系统）
* 数值逻辑是否矛盾？
* UI 流程图是否孤立节点？
* 美术标签是否一致？

输出改进建议，再由 Doc-Writer 迭代生成正式版。

---

# **3. 第二阶段技术架构细化**

## **3.1 模型层：Gemini 多模型协同**

| Agent 角色             | 推荐模型                          | 原因             |
| -------------------- | ----------------------------- | -------------- |
| Player-Agent         | Gemini Flash / Flash-Lite     | 实时响应、性价比高      |
| Mechanics / UI / Art | Gemini 3 Pro                  | 理解更细致、能处理结构化输出 |
| Doc-Writer           | Gemini 3 Pro                  | 长文本生成最佳        |
| Critic               | Gemini 3 Pro 或 Flash Thinking | 强推理能力用于审查      |

---

## **3.2 状态机层：LangGraph Orchestration（核心升级）**

状态机流程（比第一阶段更复杂）：

```
Observe → Player-Agent → Act → Record → 
    ├── Mechanics-Analyst  
    ├── UI-Agent  
    ├── Art-Agent  
    ↓
Memory Accumulate → Continue Game Loop
```

触发条件：

* 达到指定步数
* 游戏判断进入结算/失败界面
* Critic 认为信息充足

→ 进入文档生成阶段。

---

## **3.3 感知增强：加入轻量结构化视觉处理**

在第二阶段加入两个高 ROI 的本地视觉模块：

### **① OCR（文字识别）**

自动读取：

* 按钮文字（开始游戏、重试、领取奖励…）
* 数值文本（金币 1234、伤害 567、关卡 12-3）
* 装备描述/技能提示

Gemini 再基于 OCR 输出做更精细的推断。

---

### **② 简易数值测量（条形图/血条检测）**

通过 OpenCV 对常见 UI 条形元素做：

* bounding box 估算
* 相对像素比例获得 HP/XP 估计值

避免每次都让模型推断“血量大概减少了多少”。

---

## **3.4 记忆系统升级：模块化长期记忆**

对第一阶段的 `analysis_log` 进行了专业化拆分：

| 内存模块              | 内容             | 消费者                 |
| ----------------- | -------------- | ------------------- |
| `play_log`        | 行为 & 反馈的自然语言叙述 | Doc-Writer          |
| `mechanics_state` | 战斗机制、伤害事件、经济系统 | Doc-Writer / Critic |
| `ui_flow_graph`   | UI 状态机结构       | Doc-Writer          |
| `art_style_state` | 色板分析、动效风格      | 美术文档                |
| `screenshots`     | 关键截图           | Art-Agent / 文档图示    |

**优势：**

* 降低长上下文负担
* 各角色可以订阅自己需要的记忆
* 更适合作为数据集/训练素材（长期价值）

---

# **4. 第二阶段核心工作流（增强版 Agent Loop）**

与第一阶段最大差别：**Observe 后会进入多路分析，而不是单路推理。**

```
1. Observe（录制 2~5 秒视频）  
2. Player-Agent 产生 Action JSON  
3. 执行动作（pydirectinput）  
4. Record（动作后的视频反馈）  
5. 分裂处理：
      → Mechanics-Analyst（提机制、数值）
      → UI-Agent（提界面流程）
      → Art-Agent（提风格）
6. Memory 更新（各自模块）  
7. 如果未结束 → 回到步骤 1  
8. 结束条件触发 → Doc-Writer → QA-Critic → 最终文档
```

# **5. 第二阶段输出物（升级版）**

文档更标准化、可机器解析、可版本控制。

---

## **5.1 游戏策划案 GDD（结构化）**

包括但不限于：

* 游戏定位与核心循环
* 角色与成长系统
* 战斗系统（含数值公式推断）
* 关卡结构与敌人生态
* UI 流程图（自动渲染）
* 视听风格与特效设计
* 新手引导分析

---

## **5.2 数值反推表（CSV/JSON）**

* 玩家攻击公式估算
* 敌人 HP / 伤害估计表
* 技能成长曲线
* 经济系统平衡表
* 掉落概率估算（基于观测样本）

适合直接导入 Excel/BI 工具做分析。

---

## **5.3 美术风格分析报告**

* 色板图（自动提取主色调）
* UI 布局结构特征
* 动效风格（震屏、描边、粒子等）
* 参考游戏框架（自动匹配相似作品）
* 光照/渲染风格总结

# **6. 第二阶段优势：相比第一阶段的核心提升**

| 第一阶段         | 第二阶段提升点                    |
| ------------ | -------------------------- |
| 单智能体处理所有任务   | **多角色分工，逻辑更清晰、更专业**        |
| 所有分析走自然语言    | **多模块结构化记忆（更稳定、可复用）**      |
| 文档一次生成       | **加入 QA 自检，提高质量与一致性**      |
| 模型每步都要重新识别画面 | **OCR + 血条检测减负，提高准确率**     |
| 无 UI 流程图     | **自动生成 UI 状态机（可视化）**       |
| 美术分析不够系统     | **专门的 Art-Agent 做风格标签化分析** |

最终效果从「demo 级」跃升为「可以真正辅助策划团队的 AI 工具」。
